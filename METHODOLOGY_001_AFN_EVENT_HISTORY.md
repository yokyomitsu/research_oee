# Methodology 001 — Adaptive Functional Novelty Event History

Date: 2026-09-09  
Operation: exactly one G3 methodology/formalization pass  
Scope: prior-art audit and design of an auditable, cross-system evidence workflow; no implementation and no new empirical history analysis

## Decision summary

The central decision is:

\[
\boxed{\text{B — INTEGRATION GAP}}
\]

The necessary ingredients already exist. Evolutionary-activity statistics, persistence filters, neutral shadows, MODES, and the Tokyo Type 1 procedure detect and characterize long-run change. Exact lineage records, phylogenies, archived ancestors, and replay or reconstruction methods locate historical change. System-specific execution, behavioral, ecological, and intervention analyses establish causal role and adaptation. What is not explicit in existing OEE methodology is one cross-system workflow that keeps these layers separate and joins them into provenance-backed N/F/H/A/C event claims, pairwise functional-class comparisons, and censoring-aware recurrence summaries.

The result is **methodological integration**, not a new theory of evolution, a new OEE metric, or a universal function ontology.

Methodology readiness is:

\[
\boxed{\text{READY FOR RETROSPECTIVE USE}}
\]

This means ready as a manual evidence-audit protocol when published or deposited records expose the needed fields. It is not a claim that every existing history is reconstructable, nor that a software implementation or prospective reporting standard has been validated.

Exactly one next operation is selected:

\[
\boxed{\text{M1 — RETROSPECTIVE CROSS-SYSTEM APPLICATION}}
\]

It is selected but not performed here.

---

## 1. Why G3 was selected

The adaptive-functional-novelty program first found heterogeneous evidential bottlenecks across systems. Stringmol then supplied the strongest positive case: two ordered, finite AFN events—nonreciprocal parasitic exploitation and later partner discrimination. Static inspection of its deposited processed histories did not establish a third class. Avida and Geb did not provide stronger published within-history recurrence: Avida's strong lineage evidence remains largely inside enumerated task families, while Geb's long-run activity and complexity evidence is not aligned with a sufficiently resolved behavioral-event sequence.

The common residue is therefore not lack of evolutionary-change detection. It is failure to align, for a proposed event, historical appearance, causal function, heredity, adaptive establishment, class distinctness, ancestry, and provenance. [Validation 001](VALIDATION_001_STRINGMOL_ADAPTIVE_FUNCTIONAL_NOVELTY.md), [Analysis 001](ANALYSIS_001_STRINGMOL_STATIC_HISTORY_REANALYSIS.md), and [Validation 002](VALIDATION_002_AVIDA_GEB_ADAPTIVE_FUNCTIONAL_NOVELTY.md) selected G3 for that reason.

## 2. Exact methodological problem

The target is an auditable history of evidence-supported evolutionary events:

\[
\mathcal H=(e_1,e_2,\ldots,e_n),
\]

or, when histories branch or reticulate, an event graph whose lineage-specific paths can be viewed as such sequences.

The framework must answer five event-level questions under system-specific semantics:

1. What relevant capability or relation was historically new?
2. What did it causally do in its ecological or experimental context?
3. How was the organization transmitted or reconstructed?
4. What evidence links that role to selective advantage or adaptive persistence?
5. Was its causal role distinct from earlier accepted roles in the same history?

It must then report recurrence without converting a finite count into a scalar OEE score or an indefinite-capacity claim.

The cross-system commonality is logical structure and evidence provenance. Phenotype variables, function assays, clocks, ancestry relations, and causal semantics remain local to each system.

## 3. Prior-art boundary

### What existing methods already provide

| Method family | Established contribution | AFN event-history limit |
| --- | --- | --- |
| Bedau–Packard evolutionary activity | Component diversity, new activity, and cumulative activity; neutral-shadow comparison distinguishes observed persistence from a nonadaptive baseline and classifies long-run dynamics | Requires a chosen component ontology; persistent activity can occur without identification of a causal function or a class-distinct event |
| Bedau–Brown activity plots | Visual localization of adaptively significant genotype activity and population episodes | Locates candidates but does not reconstruct their functional semantics |
| Channon shadow resetting and component normalization | Keeps a neutral shadow close to the real population and improves inference about adaptive component activity; median activity avoids one permanently retained component creating a false unbounded signal | Supplies component- or population-level adaptive evidence, not automatically trait-specific function or event identity |
| MODES | Cross-system metrics for change, novelty, complexity, and ecology; persistence filtering and phylogenetic tracking reduce transient noise | The persistence filter does not remove drift completely; metrics operate on declared components and do not establish functional-class identity |
| Tokyo Type 1 procedure | Sequential test of adaptive novelty, accumulated adaptive success, diversity, complexity, indefinite scalability, and scaling order | A trend/scalability procedure, not an event-by-event semantic history |
| Stepney–Hickinbotham generic-to-specific analysis | Explicitly moves from generic measures to system-specific measures and warns that a fixed behavioral model can be escaped | Provides the core analytic principle, but not a cross-system N/F/H/A/C ledger, class-comparison rule, or event/censoring schema |
| Avida line-of-descent analysis | Exact parentage, mutation ordering, ancestral and derived program states, phenotypes, and fitness effects can reconstruct a functional origin in a digital lineage | System-specific and usually tied to configured phenotypes; does not itself supply a general cross-system class test |
| Digital phylogeny tracking and phylometrics | Lineage context, ancestry, persistence, branching, diversity, and signatures of ecology, spatial structure, and selection | Phylogenetic signal does not determine what a trait does; taxon definitions and reconstruction resolution remain consequential |
| Archived-ancestor, resurrection, and replay methods | Bound historical origin, separate potentiation from realized function, test contingency, and compare ancestral/derived effects | Powerful per-event evidence but not always available, and no universal function ontology follows |

Primary methodological sources include [Bedau, Snyder & Packard 1998](https://people.reed.edu/~mab/papers/alife6.ab.htm), [Bedau & Brown 1999](https://doi.org/10.1162/106454699568665), [Channon 2003](https://keele-repository.worktribe.com/output/403342/improving-and-still-passing-the-alife-test-component-normalised-activity-statistics-classify-evolution-in-geb-as-unbounded), [Dolson et al. 2019](https://doi.org/10.1162/artl_a_00280), [Channon 2024](https://doi.org/10.1162/artl_a_00430), [Stepney & Hickinbotham 2024](https://doi.org/10.1162/artl_a_00399), [Lenski et al. 2003](https://doi.org/10.1038/nature01568), [Moreno, Rodriguez-Papa & Dolson 2025](https://doi.org/10.1162/artl_a_00470), and [Blount, Borland & Lenski 2008](https://doi.org/10.1073/pnas.0803151105).

### Boundary result

Existing methods contain all necessary kinds of evidence, but no reviewed source makes their conjunction an explicit cross-system workflow with:

- separate discovery, reconstruction, and confirmation stages;
- one provenance-first event record;
- pairwise functional-class adjudication;
- causal/historical event deduplication;
- within-history, convergence, and platform-repertoire separation; and
- left-, right-, and interval-censoring in the final recurrence claim.

This is an **INTEGRATION GAP**, not a distinct new analytic principle. The closest prior art is Stepney and Hickinbotham's generic-to-system-specific process; the present contribution is to make the evidence join explicit and auditable for AFN.

## 4. Detection versus reconstruction versus validation

The workflow has a preparatory phase and three analytical layers.

### Phase 0 — protocol declaration

Before semantic confirmation, declare:

- the observed histories/runs and observation windows;
- the local novelty object and functional unit;
- the frozen N/F/H/A/C meanings;
- already accepted functional classes;
- candidate-discovery sources;
- minimum heredity and adaptation evidence;
- class-comparison questions; and
- treatment of censoring, duplicates, and missing data.

### Layer 1 — detection

Use any justified system-specific or generic method to nominate candidate intervals: evolutionary activity, MODES, persistence, species turnover, phylogenetic change, program/reaction changes, behavior measures, ecological-network changes, or direct historical inspection. Detection is deliberately permissive. It assigns **CANDIDATE**, not AFN.

### Layer 2 — reconstruction

For each candidate, reconstruct the defensible pre-state, derived state, carrier or population, ancestry context, causal behavior or process, ecological context, and relevant appearance/establishment chronology. A system-specific executable trace, interaction analysis, behavioral analysis, or reproductive-organization account belongs here.

### Layer 3 — validation

Apply the frozen N/F/H/A/C tests. Record criterion-level outcomes and pairwise class comparisons. A candidate becomes **AFN SUPPORTED** only when all five are supported at the declared evidence thresholds.

### Recurrence summary

Only after validation count accepted events along a continuous observed ancestry/history path. Report cross-run convergence and platform repertoire separately, together with observation windows and censoring.

## 5. AFN event semantics

The frozen decomposition remains unchanged:

- **N — novelty:** a relevant capability or relation was historically new in the observed history;
- **F — function:** it performed a system-grounded causal role;
- **H — heredity:** its organization was transmitted or reconstructed sufficiently for selection;
- **A — adaptation:** the role contributed to differential reproductive success or adaptive persistence;
- **C — class distinctness:** the causal role differed from every earlier accepted functional class in that history.

Recurrence is not an additional property of one event. It is a property of a history containing multiple validated events.

No contradiction to these definitions was found in the methodology audit. Prior art instead reinforces their separation: activity can lack semantic function, persistence can lack adaptation, exact ancestry can lack functional identity, and causal function can occur without an adaptive evolutionary origin.

## 6. Minimal event representation

The provisional tuple is useful but mixes event attributes with relations among events. The weakest adequate representation separates an event node from comparison edges.

An event node is:

\[
e_k=(I_k,L_k,\Delta X_k,F_k,H_k,A_k,P_k,S_k),
\]

where:

- \(I_k\): structured temporal interval and phase times;
- \(L_k\): history, population, and ancestry-context reference;
- \(\Delta X_k=(X_k^-,X_k^+)\): defensible pre/post contrast;
- \(F_k\): contextual functional claim and its grounding;
- \(H_k\): heredity evidence;
- \(A_k\): adaptation evidence;
- \(P_k\): first-class provenance record;
- \(S_k\): candidate/validation status and event-boundary type.

Functional class is not a self-contained event label. It is recorded as an explicit comparison edge:

\[
C_{ij}=C(e_i,e_j)\in\{\text{SAME},\text{DISTINCT},\text{UNRESOLVED}\},
\]

with declared comparison scope, evidence, and rationale. The original \(C_k\) field is therefore removed from the node and represented relationally. An event identifier is administrative rather than scientific and is omitted from the mathematical tuple, though every ledger row needs one.

The human-readable ledger is sufficient as the principal view:

| Event | Time interval | History/run | Novelty object and pre/post contrast | Functional role/grounding | Heredity | Adaptation | Functional-class relations | Provenance | Status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

Core statuses are:

- `CANDIDATE`
- `AFN SUPPORTED`
- `SAME-CLASS ADAPTATION`
- `FUNCTION UNRESOLVED`
- `ADAPTATION UNRESOLVED`
- `HEREDITY UNRESOLVED`
- `DUPLICATE EVENT`
- `PRE-EXISTING / LEFT-CENSORED`
- `MEASUREMENT-LIMITED`
- `UNCLASSIFIED NOVELTY / MODEL-ESCAPE CANDIDATE`
- `CRITERION FAILED`

Criterion fields preserve why a candidate failed; the status must not erase that information.
This vocabulary is sufficient for a retrospective audit when combined with the criterion-level fields and event-boundary label. New status terms should be added only when they mark a different evidential failure, not a more favorable interpretation.

## 7. Temporal representation

Time is normally an interval:

\[
I_k=[t_k^-,t_k^+].
\]

Where evidence permits, record distinct phase bounds:

| Phase | Meaning |
| --- | --- |
| \(I_{\mathrm{appearance}}\) | First observed existence of the relevant organization or capability |
| \(I_{\mathrm{function}}\) | First supported operation of the claimed causal role |
| \(I_{\mathrm{establishment}}\) | First interval in which adaptive establishment is supported |
| \(I_{\mathrm{persistence/fixation}}\) | Later persistence, dominance, or fixation if observed |

Fixation is not required. Appearance and adaptive establishment may be separated, including \(t_N<t_A\). They remain phases of one composite AFN claim when the later selected role is causally tied to the same historical novelty; they must not be double-counted as two AFN events.

Every event also receives one boundary label:

- `POINT EVENT` when one discrete state change is resolved;
- `TRANSITION INTERVAL` for gradual or interval-censored emergence;
- `COMPOSITE EVENT` when linked precursor, functional-origin, and establishment phases are needed;
- `UNRESOLVED EVENT BOUNDARY` when available sampling cannot choose.

## 8. Lineage / ancestry representation

Lineage grounding means a domain-justified causal descent or reconstruction relation, not one universal genealogy. Valid grounds can include parent–offspring genealogy, replicator ancestry, inheritance through copied programs, reconstructed collective descent, transmitted ecological organization, or another independently defended relation.

A tree is sufficient only for strictly branching inheritance. Horizontal transfer, recombination, fusion, symbiosis, aggregation, and cultural transmission require an ancestry graph with typed contribution edges. An event record should reference the relevant subgraph and distinguish:

- parentage/descent;
- material or informational contribution;
- recombination/fusion;
- reconstruction from transmitted constituents;
- ecological or cultural transmission when it is part of heredity.

The event-history object is therefore practically an **AFN event graph**. Event nodes can be connected by `PRECEDES`, `DESCENDS_FROM`, `ENABLED_BY`, `CONTRIBUTES_TO`, `SAME_CLASS`, `DISTINCT_CLASS`, `UNRESOLVED_CLASS`, `DUPLICATES`, and `CONVERGES_WITH`. This is a minimal typed-relation list, not a new graph theory.

## 9. Function grounding

Function is contextual and relational:

\[
F:(\text{entity or process},\text{context})
\rightarrow
\text{causal evolutionary consequence}.
\]

The event record must state the bearer/process, relevant partners or environment, operation, beneficiary or affected reproductive process, and the evidence that the operation caused the consequence. A role can disappear when the context changes; function is not an intrinsic timeless label.

Every functional claim receives one or more provenance tags:

- `DIRECT PROCESS SEMANTICS`
- `SYSTEM-SPECIFIC BEHAVIORAL ANALYSIS`
- `ECOLOGICAL INTERACTION EVIDENCE`
- `EXPERIMENTALLY SPECIFIED TASK`
- `AUTHOR INTERPRETATION`
- `ANALYST INTERPRETATION`

Externally specified tasks are not rejected. Their origin and adaptive effect can be well supported; the tag exposes the scope of the function ontology and prevents an evolved implementation from being mistaken for evolution of the task category itself.

## 10. Functional-class relation

The weakest adequate structure is a **partial, pairwise causal-role comparison**, optionally supplemented by a domain-local hierarchy. A universal taxonomy is unnecessary.

For every proposed accepted event \(e_j\), compare it with each earlier accepted class representative \(e_i\):

| Question | Purpose |
| --- | --- |
| Same causal role? | Separates function from implementation identity |
| Same beneficiary/affected process? | Detects role change hidden by similar behavior |
| Same ecological or selective problem? | Distinguishes refinement from a new relation |
| Same interaction semantics? | Distinguishes, for example, exploitation from discrimination |
| Same predeclared granularity? | Prevents retrospective narrowing or broadening |
| What evidence grounds the comparison? | Exposes analyst dependence |

The result is `SAME`, `DISTINCT`, or `UNRESOLVED`.

A strict global equivalence relation is too strong. If all comparisons use the same domain, context, granularity, and criterion, `SAME` judgments should be checked for transitive consistency. But pairwise claims made under different ecological contexts or hierarchical levels must not be closed transitively. If \(e_1\sim e_2\) and \(e_2\sim e_3\) but \(e_1\not\sim e_3\), the analyst must not manufacture a nontransitive “class”; the comparison scope is inconsistent or the middle event spans levels. Mark the affected relation `UNRESOLVED`, refine the hierarchy prospectively, and rerun the class audit under one frozen scope.

Thus pairwise comparison is sufficient for counting, while hierarchical classification is optional and global transitivity is not assumed across scopes.

## 11. Heredity evidence

The minimal ladder is:

| Level | Meaning |
| --- | --- |
| **H0 — NOT ESTABLISHED** | No defensible transmission/reconstruction relation for the functional organization |
| **H1 — CONSISTENT WITH TRANSMISSION** | Persistence or repeated appearance is compatible with heredity, but ancestry or reconstruction is not demonstrated |
| **H2 — CLEAR LINEAGE/RECONSTRUCTIVE TRANSMISSION** | Parentage, copying, ancestry, or domain-justified reconstruction transmits the relevant organization sufficiently for selection |

No extra level is needed. Intervention on transmission may strengthen H2 but is not universally available. **H2 is the minimum for `AFN SUPPORTED`.** Persistence alone can justify H1 at most.

## 12. Adaptation evidence

The qualitative ladder is:

| Level | Meaning | Typical evidence |
| --- | --- | --- |
| **A0 — NOT ESTABLISHED** | No link to differential reproductive success or adaptive persistence | Appearance only |
| **A1 — CORRELATIONAL** | Trait/function covaries with abundance, persistence, or success, with plausible alternatives remaining | Population rise, temporal association |
| **A2 — COMPARATIVE / LINEAGE SUPPORT** | Matched alternatives, lineage replacement, sister-lineage comparison, repeated convergence, loss/regain dependence, or context comparison supports selection on the role | Competitions, consistent displacement, environment-dependent advantage |
| **A3 — STRONG CAUSAL / INTERVENTION SUPPORT** | Direct manipulation, knockout/rescue, reconstructed mutation, or controlled counterfactual changes the relevant reproductive consequence | Ablation, replay, matched intervention |

**A2 is the minimum for `AFN SUPPORTED`; A3 is not universally required.** A1 remains `ADAPTATION UNRESOLVED`. Direct execution semantics may establish F strongly without establishing A.

Counterfactual usefulness strengthens an event: would the subsequent adaptive trajectory or reproductive consequence differ without the functional change? Literal intervention is optional. Sister lineages, archived ancestors, independent convergence, loss/re-emergence, environmental dependence, exact execution semantics tied to reproduction, and known reaction consequences can supply bounded substitutes. Each substitute must state what counterfactual it supports.

An excess over a neutral or reset shadow can support population- or component-level adaptive activity. It reaches event-level A2 only when the measured component is explicitly aligned with the reconstructed functional carrier and plausible linked alternatives are controlled. Otherwise it remains Layer-1 discovery/background evidence and cannot be borrowed as causal support for the event.

## 13. Provenance

Provenance is part of the event node, not an appendix. \(P_k\) contains:

- dataset/deposit and immutable version or checksum where available;
- system, experiment, run, and population identifiers;
- observation window and sampling resolution;
- exact time interval and ancestry subgraph identifiers;
- files, figures, tables, traces, checkpoints, or archived organisms used;
- detection and reconstruction methods, parameters, and transformations;
- publication and author analysis;
- analyst-added interpretation and its date/version;
- frozen protocol/class definitions used for confirmation;
- missing, corrupt, lossy, or unavailable evidence.

Multiple publications or metrics supporting one event become multiple provenance entries, not multiple events.

## 14. Event deduplication

Two records are duplicates when they refer to the same historical state transition or establishment episode in the same ancestry context and their claimed effects are causally inseparable at the frozen functional granularity.

Deduplication proceeds in this order:

1. match history/run and ancestry context;
2. compare appearance/establishment intervals;
3. compare pre/post state contrast and carriers;
4. compare causal role and beneficiary;
5. merge metric, figure, file, and publication evidence into provenance;
6. retain separate events only when independent roles have separate causal grounds or occur in distinct historical origin/establishment episodes.

One mutation may have several phenotypic consequences but still be one composite event. Conversely, one functional innovation may require several mutations and remain one AFN event. The causal/historical unit, not the number of measurements, mutations, papers, or phenotype labels, controls counting.

## 15. Convergence / recurrence / platform repertoire

Three summaries are mandatory and independent:

| Summary | Meaning | Effect on AFN count |
| --- | --- | --- |
| `WITHIN-HISTORY EVENT COUNT` | Validated class-distinct events along one continuous observed ancestry/history | The only finite recurrence count |
| `CROSS-RUN CONVERGENCE` | Independent origin of the same function in multiple histories | Strengthens adaptation/reproducibility; does not add a class to one history |
| `PLATFORM-WIDE REPERTOIRE` | Functions demonstrated anywhere across experiments/configurations | Capability/evidence inventory; never a recurrence sequence |

The canonical rule is:

\[
\boxed{\text{functions evolved in separate experiments}
\neq
\text{repeated AFN within one history}.}
\]

## 16. Composite innovations and exaptation

For a multi-step innovation, record typed phase or precursor relations:

- `ENABLING CHANGE` changes access or background but does not yet supply the function;
- `POTENTIATING EVENT` raises later probability or expressibility;
- `FUNCTIONAL-ORIGIN PHASE` first realizes the causal role;
- `ADAPTIVE-ESTABLISHMENT PHASE` supplies A2/A3 evidence;
- `OPTIMIZATION EVENT` improves an established role and is normally same-class.

Only the integrated origin-plus-establishment record can become AFN. Enabling and optimization steps are not separately counted unless they themselves acquire independent N/F/H/A/C roles.

Exaptation separates structural origin from functional origin. An old structure entering a new adaptive causal relation can be a new AFN event even though the structure is not new. The event's N claim concerns the role/relation, while provenance points back to the earlier structural origin. This preserves the repository's Q005/Q015 boundary.

## 17. Loss and re-emergence

For a trajectory \(F_1\rightarrow\neg F_1\rightarrow F_1'\), record:

- a `LOSS EVENT` when the function ceases;
- `REGAIN` when the same heritable implementation returns;
- `INDEPENDENT RE-ORIGIN` when a new ancestry produces the same role;
- `NEW IMPLEMENTATION / SAME CLASS` when mechanism changes but role does not;
- `NEW FUNCTIONAL CLASS` only when the causal role changes and all N/F/H/A/C tests pass.

A previously validated event remains historical even if later lost. Regain and convergence can strengthen ecological/adaptive interpretation but do not add a new functional class. This rule blocks defense loss/reappearance from inflating recurrence counts.

## 18. Censoring and sampling resolution

Every history declares \([T_{\min},T_{\max}]\), sampling interval or event-log resolution, and gaps.

- **Left censoring:** functions present at \(T_{\min}\) are `PRE-EXISTING / LEFT-CENSORED`; their origin is not counted.
- **Right censoring:** no later event by \(T_{\max}\) means only non-observation before that limit.
- **Interval censoring:** a change between observations is bounded by the last negative and first positive observation.
- **Resolution limit:** events or intermediates shorter than \(\Delta t\) may be missed; absence below that scale is not inferred.

The required language is:

\[
\boxed{\text{no later AFN observed by }T_{\max}}
\]

and never, on that evidence alone, “AFN exhausted.” If a proposed earlier-role absence is limited by sampling, use `EARLIER EQUIVALENT NOT FOUND AT RECORDED RESOLUTION` rather than `PROVEN ABSENT`.

## 19. Measurement escape

Generic and system-specific detectors embody behavioral models. A later change outside those models receives:

`UNCLASSIFIED NOVELTY / MODEL-ESCAPE CANDIDATE`.

This status requires a concrete anomaly—such as unexplained persistent lineage, reaction, behavior, or interaction change—not speculation about hidden novelty. It is excluded from AFN counts until new system-specific reconstruction establishes N/F/H/A/C. Stepney and Hickinbotham's warning therefore limits negative conclusions without converting missing measurement into positive evidence.

## 20. Ongoingness evidence

The proposed O0–O4 ladder should **not** be adopted as one universal ordinal. Its higher levels mix event count, observation length, resource scaling, saturation, and stochastic extrapolation.

Use a two-part report instead:

1. **Validated within-history event count:** 0, 1, or finite \(n\), with class-comparison confidence.
2. **Continuation evidence:** one of
   - `NO RECURRENCE OBSERVED`;
   - `FINITE RECURRENCE OBSERVED`;
   - `EXTENDED RECURRENCE; NO SATURATION DETECTED WITHIN DECLARED WINDOW`;
   - `STATISTICAL CONTINUATION SUPPORT UNDER DECLARED MODEL`;
   - `INDEFINITE AFN NOT ESTABLISHED`.

The last statement accompanies every finite study. “No saturation detected” is an observation-window result, not proof of capacity. Statistical continuation requires a justified event-generating model, diagnostics, and sensitivity analysis; it is not implied by three events.

Evidence for `OBSERVED FUNCTIONAL-CLASS SATURATION` requires a declared function ontology and resolution, substantial continued evolutionary opportunity, ongoing same-class adaptation or cycling, and no new validated class across the stated window. Even then the claim concerns the observed regime. It is not `CAPACITY EXHAUSTION`.

## 21. Event-rate limitations

AFN events can be rare, dependent, nonstationary, lineage-specific, and capable of changing later event structure. A Poisson or renewal process is therefore never the default.

Event-rate reporting is:

- avoided for 0–2 events except trivial descriptive counts per declared window;
- optional and descriptive at low counts;
- inferential only when a generative event model is justified, event definitions are stable, observation effort is modeled, and nonstationarity/dependence are tested;
- accompanied by censoring and sensitivity to event granularity.

No universal AFN rate is part of the methodology.

## 22. Cross-system comparison

Counts such as Stringmol 2, Avida 1, and Geb 1 are comparable only in the restricted sense:

\[
\boxed{\text{validated distinct AFN events inside one continuous observed history}}
\]

under the same logical N/F/H/A/C protocol and system-specific functional interpretation.

The functions, clocks, substrates, event magnitudes, ecological contexts, and observation efforts are not numerically commensurable. Every comparison table must therefore include window length, resolution, censoring, evidence levels, and function-grounding source.

Event count is an evidence summary, not an OEE score. More events do not universally mean “more OEE”; counts ignore duration, ecological richness, branching, event magnitude, sampling, and opportunity.

## 23. Relation to Tokyo Type 1

The two methods are complementary:

\[
\boxed{\text{Tokyo Type 1 trends}
+
\text{AFN event history}}
\]

Tokyo Type 1 tests whether adaptive novelty, accumulated adaptive success, diversity, and complexity show the required long-run and scalability patterns. AFN event history asks what causal functions constitute candidate adaptive novelty and whether they form a class-distinct within-history sequence.

AFN history can audit the semantic content of a Tokyo trend. Tokyo analysis can test whether a finite event sequence sits inside sustained adaptive and complexity dynamics. Neither replaces the other: a system may have strong component activity without reconstructed functional events, or two finite AFN events without Tokyo Type 1 ongoingness/scalability.

## 24. Relation to MODES

MODES is suitable for **Layer 1 candidate discovery** and background characterization. Its change, novelty, complexity, and ecological metrics can localize unusual histories or intervals; its lineage-persistence filter can remove many transient mutants; its phylogenetic machinery supplies ancestry context.

MODES does not already provide the full AFN event object. Its components are user-defined, persistence is not equivalent to adaptation, and its metrics do not determine causal function or pairwise class identity. When a MODES component is itself a rigorously defined function and its adaptive effect is separately supported, its output can populate parts of an event record; the N/F/H/A/C audit remains explicit.

## 25. Relation to Stringmol's generic-to-specific analysis

Stepney and Hickinbotham already establish the central analytic direction:

\[
\text{system-generic measure}
\rightarrow
\text{system-specific analysis}.
\]

G3 does not claim that principle as new. It adds an explicit cross-system evidence schema around it:

\[
\text{candidate detection}
\rightarrow
\text{causal reconstruction}
\rightarrow
\text{N/F/H/A/C validation}
\rightarrow
\text{deduplicated, censored event graph}.
\]

This makes confirmation criteria, functional-class granularity, ancestry, and provenance auditable. Measurement escape remains an open candidate status rather than a license to infer unmeasured AFN.

## 26. Phylogeny contribution

Phylogenies can supply:

- lineage and branching context;
- ancestor–descendant order;
- lineage persistence and establishment proxies;
- independent-origin/convergence identification;
- sister-lineage comparisons;
- ecological, spatial, and selection signatures;
- resolution checks for reconstructed histories.

Exact digital tracking is especially valuable because parentage can be recorded rather than inferred. Hereditary stratigraphy and reconstruction algorithms offer scalable alternatives when exact tracking is costly. Moreno, Rodriguez-Papa, and Dolson show that ecology, spatial structure, and selection pressure leave detectable but overlapping phylogenetic signatures, and that low-resolution reconstruction can bias metrics.

The boundary is strict:

\[
\boxed{\text{phylogenetic signal}\not\Rightarrow\text{functional identity}.}
\]

A phylogeny supplies L, parts of H, and sometimes comparative support for A. F and C still require system-specific reconstruction unless phenotypes/functions are already encoded and causally grounded.

## 27. Counterexamples A–J

| Case | Required classification |
| --- | --- |
| **A. Thousands of persistent genotypic novelties, no functional novelty** | Layer-1 activity/novelty; no F, so no AFN. Persistence does not promote them. |
| **B. One new adaptive function realized by many genotypes** | One functional event/class, potentially many carriers and implementations; deduplicate. |
| **C. Two distinct mechanisms solve one function** | First origin may be AFN; second is `NEW IMPLEMENTATION / SAME CLASS` unless its causal role differs. |
| **D. One old mechanism acquires a new function through exaptation** | Structural origin remains earlier; new role can be AFN if N-of-role/F/H/A/C pass. |
| **E. A function appears but never establishes** | `CANDIDATE`, A0/A1; no AFN. Record appearance and loss. |
| **F. An adaptive function appears and is later lost** | AFN remains supported if establishment reached A2; loss is a separate event and weakens ongoingness, not historical validity. |
| **G. The same function evolves independently in several runs** | Cross-run convergence; strengthens A/reproducibility, does not increase within-history class count. |
| **H. Two functions emerge in unrelated experiments on one platform** | Platform-wide repertoire of two; each history retains its own count. No recurrence sequence. |
| **I. A function emerges gradually with no sharp origin** | `TRANSITION INTERVAL` or `COMPOSITE EVENT`; no forced point time and no multiplication of AFN counts. |
| **J. Later novelty escapes the behavioral measurement model** | `UNCLASSIFIED NOVELTY / MODEL-ESCAPE CANDIDATE`; no AFN until semantic reconstruction. |

The cases separate genotype count, mechanism count, function count, event count, and platform repertoire as required.

## 28. Retrospective-analysis bias

Historical datasets cannot be prospectively preregistered after collection. Realistic mitigation is nevertheless possible:

1. time-stamp the analysis protocol and freeze N/F/H/A/C, existing classes, and evidence thresholds before confirmation;
2. separate exploratory candidate discovery from confirmation, even when both use the same archive;
3. retain a complete candidate ledger, including failures and negative controls;
4. declare every inspected run, window, exclusion, and missing file;
5. merge duplicate publications/metrics by causal event identity;
6. report sensitivity to class granularity without choosing the favorable granularity after seeing the outcome;
7. use independent adjudication or blinded event summaries where practical;
8. distinguish author interpretation from analyst interpretation;
9. avoid arbitrary post hoc change thresholds;
10. label same-data confirmation `RETROSPECTIVE / EXPLORATORY CONFIRMATION` when no independent holdout or replication exists;
11. state publication-selection limits, especially when only spectacular endpoint examples were published.

This freezing principle is methodological discipline, not a demand that old experiments satisfy impossible prospective preregistration.

## 29. Minimum future data requirements

An ALife experiment should retain only the evidence needed to reconstruct the event graph:

1. **Run identity and conditions:** immutable configuration, software/model version, parameter changes, random seed where appropriate, observation bounds, and clock definition.
2. **Ancestry/transmission:** parent–offspring or typed contribution edges, including recombination, transfer, fusion, and reconstruction relations where relevant.
3. **Heritable state checkpoints:** genotype/program/developmental state sufficient to recover pre/post organization.
4. **Phenotype/function evidence:** behavior, execution, reaction, interaction, or reproductive-organization descriptors plus enough trace data for causal interpretation.
5. **Evolutionary consequences:** births, copies, survival/persistence, resource capture, competitive outcomes, or other local reproductive consequences linked to carriers and contexts.
6. **Environment/ecology:** relevant partner identities, resources, spatial/ecological state, and environmental changes.
7. **Temporal coverage:** appearance, abundance/persistence, sampling interval, missing intervals, and final observation time.
8. **Provenance:** raw/deposited identifiers, checksums/versions, transformations, and mappings from publications/figures to records.

Complete raw-state retention is not universally required. The requirement is lossless preservation of the declared ancestry, state contrast, function, and adaptive evidence at sufficient temporal resolution. This is a data-content specification, not a software architecture.

## 31. Strongest prior-art absorption test

The strongest absorption proposal is:

\[
\boxed{
\text{AFN event-history methodology}
=
\text{existing OEE metrics}
+
\text{persistence/phylogeny}
+
\text{system-specific interpretation}
}
\]

This proposal succeeds at the level of scientific ingredients:

- activity, MODES, and Tokyo measures detect candidate dynamics and trends;
- persistence and shadows help distinguish signal from transient or neutral background;
- phylogenies and line-of-descent records ground ancestry and historical order;
- execution/behavior/ecology reconstruct function;
- lineage comparisons and interventions support adaptation;
- existing historical-evolution methods distinguish potentiation, origin, establishment, optimization, loss, and replay.

It fails only as a ready-made explicit workflow. No reviewed method requires the complete provenance join, keeps C as a frozen pairwise relation, deduplicates causal events across measures/publications, separates three recurrence summaries, and carries censoring into the final AFN claim.

Therefore G3 is not a new formalism in the strong sense. It is a useful **cross-system evidence-integration schema** assembled from established methods.
